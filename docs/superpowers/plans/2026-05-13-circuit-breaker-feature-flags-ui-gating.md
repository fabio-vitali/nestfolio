# Circuit-Breaker Feature-Flag UI-Gating Fix Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix scenario 14 e2e (`apps/e2e-feature-tests/src/account/circuit-breaker-lifecycle.e2e.test.ts`) — when `withBreakerOpen()` writes a `CircuitBreaker#alpaca` row, the 3 gated feature flags (`confirmDecision`, `initiateDeposit`, `requestWithdrawal`) must flip to `enabled:false` via `getFeatureFlags` within the 120s test budget, and re-enable when the breaker closes.

**Architecture:** Discovery-driven bug fix. The in-handler logic is unit-test-verified correct (broadcast-listener.ts fires 3 mutations on `BROKER_CIRCUIT_OPEN` via `broadcastFromQueue`). Bug lives in one of 4 propagation layers: (a) CDC emission, (b) EB cross-bus routing, (c) IAM-signed runtime call, (d) read path. Plan structure: enable telemetry → walk layers top-down → fix at first-failing layer → place regression test at the layer's closest reusable test boundary → validate 3× green.

**Tech Stack:** Jest (e2e + integration + unit), CDK (Facade construct, EB rules, declarative eventTypes), AppSync JS resolvers, CloudWatch Insights + Metrics, DynamoDB (CircuitBreaker + FeatureFlag rows), EventBridge cross-bus rules, `@nestfolio/event-processor` (broadcastFromQueue pipeline).

**Spec:** `docs/superpowers/specs/2026-05-13-circuit-breaker-feature-flags-ui-gating-design.md`

    const table = await ctx.ssm.tableName('investor-bff');
    const ddb = DynamoDBDocumentClient.from(new DynamoDBClient({ region: ctx.region }));
    const r = await ddb.send(new GetCommand({
      TableName: table,
      Key: { pk: 'FeatureFlag#SYSTEM', sk: `FeatureFlag#${name}` },
    }));
    if (!r.Item) return null;
    return { enabled: r.Item['enabled'] as boolean, reason: (r.Item['reason'] as string) ?? null };
  }

    await Promise.all(flags.map(name =>

        Item: { pk: 'FeatureFlag#SYSTEM', sk: `FeatureFlag#${name}`, __typename: 'FeatureFlag', name, enabled: true, reason: null },

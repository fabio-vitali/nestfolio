**Failure 2 — `sec-edgar-adpt`** (3 tests pass, afterAll fails)
```
thrown: "Exceeded timeout of 60000 ms for a hook."
  at afterAll ... sec-edgar-adpt.integration.test.ts:68

```
- Hook body: `await ctx.cleanup.runAll();` — LIFO runs EventBusTrap → TableAssertions → SsmOverrideFixture → MockApiFixture → SsmCache.
- Two distinct problems:
  - **Slow**: the full chain can exceed 60 s under load (Lambda DeleteFunction + IAM DetachRolePolicy + DeleteRole + SSM PutParameter + DeleteParameter + SQS DeleteQueue run serially; 60 s afterAll is tighter than the 90 s beforeAll).

Undestroyed v3 SDK clients keep connection pools open → Jest's "did not exit" warning.

**Failure 3 — `advisory-ctrl`** (detail truncated)
- Output in the pasted log shows `✖ nx run advisory-ctrl:test-integration` with no stack trace.
- Uses `MockApiFixture` + `SsmOverrideFixture` + `OrphanReaper` + `EventBusTrap` (same fixtures as sec-edgar), same 60 s afterAll cap — cleanup-timeout is a plausible hypothesis but unverified.
- Could alternatively be a real regression in one of 16 test cases (3 compliance, 2 user-response, 11 agent-trigger `it.each`).

```typescript
    if (!this.paramName || !this.backupParamName || !this.restoreTo) return;

```

Replace with:
```typescript
  async restore(): Promise<void> {
    try {
      if (!this.paramName || !this.backupParamName || !this.restoreTo) return;
      // Always restore to the caller-provided canonical value. We pass it through
      // memory rather than reading from .backup so a corrupted .backup cannot
      // re-poison the live parameter.
      await this.client.send(new PutParameterCommand({
        Name: this.paramName,
        Value: this.restoreTo,
        Type: 'String',
        Overwrite: true,
      }));
      // Delete .backup — clean slate for next run
      await this.client.send(new DeleteParameterCommand({
        Name: this.backupParamName,
      }));
    } catch (err) {
      // eslint-disable-next-line no-console
      console.error('SsmOverrideFixture: failed to restore SSM value', err);
    } finally {
      this.client.destroy();
    }
  }
```

Note: moved the early-return inside the `try` and added `finally` so `destroy()` runs even when the fixture was never activated. This matches the test expectation and prevents handle leaks in failure paths.

# Fresh worktree missing host runtime config silently breaks Playwright

## Evidence

- `apps/nestfolio-host/public/assets/config.json` is listed in repo `.gitignore` — it is generated by `pnpm nx run nestfolio-host:config --prefix=dev` (target reads SSM exports for the dev account and writes JSON).
- A freshly-created git worktree does NOT have this file. The host then SPA-falls-back `/assets/config.json` to `index.html`, the browser console reports:
  ```
  Federation init failed
  Error: Runtime config malformed at /assets/config.json: SyntaxError: Unexpected token '<', "<!doctype "... is not valid JSON.
  Re-run `pnpm nx run nestfolio-host:config --prefix=<prefix>`.
  ```
- Playwright then fails at `OnboardingChatPage.waitForRenderer('render_options', 60_000)` — a misleading "render_options never appeared" error, because the MFE shell itself never loaded.
- Surfaced 2026-05-24 during the agentcore-maxvms-browser-path-resilience Task 3 validation — ~5 min lost to misdirection before reading the trace's console error.

## Cheapest fix

Two options:
1. **Postinstall hook** — `package.json` postinstall runs `pnpm nx run nestfolio-host:config --prefix=dev` (gated to dev-account credentials being available).
2. **Nx target dependency** — make `apps/nestfolio-e2e:e2e` depend on `nestfolio-host:config`. Cleaner because it only runs when e2e runs (no install-time AWS coupling).

Option 2 is preferred: e2e already needs SSM access for the proxy target (`apps/nestfolio-e2e/playwright.config.ts:20-34`).

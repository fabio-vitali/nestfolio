# Deterministic CLAUDE.md service-card-drift gate

## Why

Service cards (`services/*/CLAUDE.md`) are regenerated on-demand by `audit-service` via an
LLM read→rewrite, with **no standing gate** — so code silently drifts from the card. A
deterministic checker that diffs the mechanically-derivable card sections against the code
closes the *class* of drift, the same way `check-read-model-drift.mjs` and
`check-typed-subjects.mjs` (the typed-subject capstone) close theirs.

## Scope

A `tools/check-service-card-drift.mjs` (mirroring `check-read-model-drift.mjs`: pure Node,
exclusion registry, nx target on a host project + pre-commit) that parses each service's
`service.stack.ts` / `events.ts` and diffs the **machine-derivable** card sections against
`CLAUDE.md`:

- Ingress event subscriptions
- Egress `eventTypes` map
- Handlers
- Event Types
- DDB entities

Fail CI on mismatch. Prose / intent / narrative sections stay LLM-regenerated by
`audit-service` and are **not** gated. May warrant a brief design pass on exactly which
sections are reliably derivable.

## Known-stale cards to fix when the gate lands (from the subsumed funding-drift item)

- `services/execution/broker-ctrl/CLAUDE.md` — Egress/Ingress/Event-Type sections stale
  w.r.t. funding-lifecycle + FundingEvent-CDC; `WITHDRAWAL_INITIATED` vs `WITHDRAWAL_REQUESTED`.
- `services/investor/investor-adpt/CLAUDE.md` — `InvestorIngestEventTypes` still names
  `WITHDRAWAL_COMPLETED`/`TRANSFER_FAILED`; code now uses `DEPOSIT_REQUESTED/SETTLED/FAILED`,
  `WITHDRAWAL_REQUESTED/SETTLED/FAILED`.
- `services/investor/investor-bff/CLAUDE.md` — Ingress + `event-listener.ts` handler line
  omit the full `DEPOSIT_*`/`WITHDRAWAL_*` funding-lifecycle subscriptions the handler wires.

(Also note: several cards' "dependencies/imports" lines were just repointed to `*-adpt/domain`
by the typed-subject capstone — a good first regression target for the gate.)

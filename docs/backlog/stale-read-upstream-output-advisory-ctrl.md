# Stale `session.readUpstreamOutput('advisory-ctrl')` in advisory AgentCore graphs

Surfaced 2026-05-06 during Operating Mode Phase 2 implementation. Three AgentCore graph.ts files call `session.readUpstreamOutput('advisory-ctrl')`:

1. `services/advisory/portfolio-engine-ctrl/agents/portfolio-engine/graph.ts:97`
2. `services/advisory/advisory-narrative-ctrl/agents/advisory-narrative/graph.ts:76`
3. `services/advisory/market-intelligence-ctrl/agents/market-intelligence/graph.ts:85`

(Original backlog notes mentioned only the first two — the third was found while verifying references against code at promotion time.)

advisory-ctrl was REMOVED 2026-04-30 in Spec 2 (advisory pipeline consolidation), so the namespace `/advisory-ctrl/{tenantId}/decisions/{decisionId}` is never written to. Result: `upstreamRecords` is always `[]`, `upstreamContext` always `''`. Latent — agents have been losing a context channel since 2026-04-30 ship without anyone noticing.

The actual upstream context arrives via `payload.upstreamOutputs`, populated by the Lambda event-listener (e.g. `services/advisory/portfolio-engine-ctrl/src/handlers/event-listener.ts:29-33`) before the AgentCore Runtime call. So the in-graph Memory read is pure dead weight — no replacement read needed.

## Fix

Delete the dead reads + the `+ upstreamContext` concat in each of the three graph.ts files. Also delete the orphaned `it('reads upstream memory context', …)` test in `services/advisory/advisory-narrative-ctrl/test/unit/graph.test.ts:83-104` which asserts the buggy `toHaveBeenCalledWith('advisory-ctrl')` behavior.

## Done definition

- All three graph.ts files no longer reference `'advisory-ctrl'`.
- `pnpm nx run-many -t test -p portfolio-engine-ctrl,advisory-narrative-ctrl,market-intelligence-ctrl` green.
- `grep -r "readUpstreamOutput.*advisory-ctrl" services/` returns zero matches in `.ts` source (`dist/bundle.js` allowed — regenerated on next deploy).

# Red-team hardening — the mechanical fixes

The confirmed, deterministic subset of `runtime-design-redteam` findings — no contract re-freeze needed
(those route to `runtime-seam-probe` and `runtime-backward-edge-live`), just fixes + regression tests:

1. **Fail-closed registry**: `pre-commit-gate.mjs` (and `run-watch.mjs` main) must treat
   `loadRegistry().errors[]` as blocking — a corrupted check YAML currently narrows enforcement silently.
2. **`--diff-filter=ACMR`**: `readStaged` misses renames; `git mv` + edits bypasses the gate today.
3. **Atomic + guarded `meta.json`**: write-tmp-then-rename; guard `JSON.parse` (torn meta currently
   bricks the run with no heal, unlike the tail-healed steps ledger).
4. **Journal concurrency**: the root is deliberately shared across worktrees but `begin`/`step` are
   unlocked check-then-act — add locking or an enforced single-writer rule per runId.
5. **Runnable `registry-integrity`**: both rings register `cmd:node …/meta-check.mjs`, which is a usage
   stub (exit 2, empirically verified) — give the meta-check a loaded-registry CLI so the registry's
   self-check actually runs.
6. **`single-active` semantics**: the starter check requires exactly-one and counts epics — align with
   the real law (≤1 non-epic active, ≤1 active epic; zero legal between workstreams). Empirically exits
   1 on today's legal state.
7. **Starter-pack self-containment**: 3 of 6 starter checks invoke Nestfolio-only files (`tools/…`,
   `.claude/skills/…`) — starter evaluators must ship inside `runtime/` or be generated by `init`.
8. **cmd-attribution scope drift**: cmd evaluators ignore `check.scope` for attribution and at least one
   registry scope has diverged from its tool's filters (`no-states-runtime-catch`).

Source: `runtime-design-redteam` verdict (2026-07-03). Sequenced P2 — with or right after
`runtime-backward-edge-live`, before the bulk migration triples enforcement on these mechanisms.

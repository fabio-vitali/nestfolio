## 5. Seeding Mechanism

### 5.1 Seed Script

A CLI script in `tools/scripts/seed-data.ts` runs against the dev/staging AWS account and populates all required DynamoDB tables and S3 buckets.

```bash
# Run the seed script
npx ts-node tools/scripts/seed-data.ts --stage dev --persona all

# Or seed a single persona
npx ts-node tools/scripts/seed-data.ts --stage dev --persona maria
```

### 5.2 Seeding Steps

The seed script populates foundational data directly, then **invokes the actual agent pipeline** to generate decisions and explanations. This validates the entire end-to-end flow as part of seeding.

**Phase A -- Direct writes (foundational data):**

1. **Upload market data** to S3 (`etf-prices.json`)
2. **Create Cognito users** (Maria, Luca, Sofia) with pre-verified email addresses
3. **Write InvestorProfile records** to `investor-bff` DynamoDB table (goals, risk profile, operating mode, mandate)

**Phase B -- Pipeline invocation (decisions via real agents):**

4. **Publish `MANDATE_GRANTED` events** to EventBridge for each persona. These are real domain events that trigger the full pipeline: `advisory-ctrl` receives the event -> AgentCore Runtime invokes the Portfolio Analyst and Explainability agents -> `compliance-ctrl` validates the proposal -> `execution-adpt` records virtual trades -> `portfolio-bff` and `advisory-bff` projections update.
5. **Publish subsequent trigger events** (`DEPOSIT_DETECTED`, `DRIFT_DETECTED`, `GOAL_UPDATED`, `RISK_PROFILE_UPDATED`) per persona to generate the additional decision scenarios listed in Section 2.
6. **Wait for pipeline completion** by polling the advisory-bff projection for expected DecisionPacket records (with a configurable timeout).

**Phase C -- Result caching:**

7. **Snapshot the generated results** to a local cache file (`seed-cache/{stage}/seed-snapshot.json`). On subsequent runs, the script can use `--use-cache` to skip pipeline invocation and directly write the cached records, enabling fast reseeding without LLM costs.

**Fallback**: If the agent pipeline fails during seeding (e.g., LLM provider outage), the script falls back to writing pre-computed explanation content from `seed-data/fallback-explanations.json` (the hardcoded JSON in Section 6). This ensures seeding always succeeds, but the primary path exercises the real system.

### 5.3 Idempotency

The seed script is idempotent -- running it multiple times produces the same result. It uses `PutItem` with the full item (overwrites existing), not `UpdateItem`. To reset, run the script again.

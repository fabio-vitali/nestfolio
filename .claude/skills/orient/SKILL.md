## When This Skill Applies
- Starting a new conversation and need system context
- Asked to explain the architecture
- Need to understand how components relate before making changes

## Where to Read (canonical sources)

This skill is intentionally thin. Anything that changes when the system changes lives in the architecture docs, not here. Read in this order:

1. **`docs/architecture/SYSTEM-ARCHITECTURE.md`** — cross-cutting "why". Sections most useful for orientation:
   - §2 Product Summary
   - §4 High-Level System Domains
   - §5 Core Architectural Principles
   - §13 Decision Lifecycle (End-to-End)
   - §20 Frontend Topology
2. **`docs/architecture/SERVICE-INVENTORY.md`** — canonical per-service "what". The "Inventory Summary" table is the authoritative service list (count, domain, type, MFE, agent, health). Per-service entries follow.
3. **Per-service `CLAUDE.md` cards** at `services/{domain}/{svc}/CLAUDE.md` — code-anchored detail (subscriptions, handlers, dependencies, tests). Regenerable via the `audit-service` skill.
4. **`flows/*.flow.yaml`** — end-to-end business flows. Generated by `generate-flow-spec`, validated by `validate-flow`.

## Stable Conventions (low-drift, fine to keep inline)

| Suffix | Role | Has State? |
|--------|------|-----------|
| `-ctrl` | Domain logic, orchestration | Yes |
| `-bff` | Backend-for-Frontend (GraphQL/REST) | Yes |
| `-hub` | Event aggregation, projection store | Yes |
| `-adpt` | Cross-domain event ingestion OR external integration | Mixed |
| `-web` | Angular shell host | Browser only |

| What | Where |
|------|-------|
| Service stack | `services/{domain}/{svc}/src/service.stack.ts` |
| Service handlers | `services/{domain}/{svc}/src/handlers/` |
| Event types | `services/{domain}/{svc}/src/domain/events.ts` |
| Unit tests | `services/{domain}/{svc}/test/unit/` |
| Integration tests | `services/{domain}/{svc}/test/integration/` |
| Service card | `services/{domain}/{svc}/CLAUDE.md` |
| Flow specs | `flows/*.flow.yaml` |
| Architecture refs | `docs/architecture/SYSTEM-ARCHITECTURE.md` + `SERVICE-INVENTORY.md` |

## Anti-Patterns
- NEVER import from `services/` — only from `libs/`
- NEVER call between services via API — events only
- NEVER write raw Lambda handlers — use event-processor pipelines
- NEVER hand-edit service cards — run `audit-service` to regenerate
- **NEVER enumerate services, MFE lists, or event lists in this skill** — those drift on every system change. Cite the canonical doc instead.
